# 发布新版本（维护者）

发布包 = 版本库里的全部文件 + 编译好的 `worldmod/build/d3d9.dll`。DLL 由 GitHub Actions 从源码编译，
不用你上传自己电脑上的文件，别人也能确认 DLL 和源码一致。

## 第一次：建仓库

在项目目录里：

```bat
git init
git add .
git commit -m "首次发布"
gh repo create 仓库名 --public --source . --push
```

`git add .` 只会加入 `.gitignore` 没排除的文件。提交前用 `git status` 看一眼：不应该出现 `.exe`、`.s11`、
`san11pkres.bin`、`data/china_*.npy`、`project.json`。

## 每次发版

1. 改完代码和文档，提交并推送：`git commit -am "说明" && git push`
2. 打一个版本标签并推送：

```bat
git tag v0.1
git push origin v0.1
```

3. 等几分钟，GitHub 的 Actions 页面里 `release` 跑完，Releases 页面就会出现 `v0.1`，
   附件是 `san11-world-v0.1.zip`，说明文字来自 `tools/make_release.py` 里的 `NOTES`。

想先试一下能不能编译、不发布：在 Actions 页面选 `release`，点 Run workflow；生成的 zip 在那次运行的 Artifacts 里。

## 在自己电脑上打包

```bat
python san11kit.py dll
python tools/make_release.py --version v0.1-test
```

包在 `dist/` 里。`make_release.py` 只打包 git 跟踪的文件，并且发现游戏文件（`.exe`、`.s11`、`san11pkres.bin`、
提取出的中国地图）会拒绝打包。

## 版本号

`v主版本.次版本`：剧本、地图格式不兼容（旧存档读不了、旧剧本 JSON 要改）时加主版本，其余加次版本。
存档和城市数绑定，城市数变了要在发布说明里写清楚。
