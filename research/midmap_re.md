## 1. 类与生命周期

### 1.1 中地圖对话框（宿主）

* vt 0x858598，基类是通用对话框（ctor 0x4d79b0，vt 0x833718）。ctor 0x6386e0；非虚 dtor 0x638490；vt[0] 0x6387e0 = 删除型 dtor。
* 大小 **0x95c**：0x61d1c0 的栈帧里对象在 esp0+0x44，安全 cookie 在 esp0+0x9a0；ctor 写到的最后一个字段是 +0x958。
* 重写的虚函数：
  * vt+0x004 **0x635a80** Destroy：依次销毁 4 个子面板，然后 `MapUI->vt[0](1)` 并清零 +0x1a0。
  * vt+0x118 **0x636d90**：按钮按下 / 复选框勾上（见 §4.4）。
  * vt+0x11c **0x637040**：复选框取消勾选（清掉对应位）。
  * vt+0x158 **0x638520**：MapUI 通知「悬停对象变了」，右上信息卡显示该据点或部队。
  * vt+0x15c **0x636c80**：MapUI 通知「选中 / 取消选中据点」。
  * vt+0x1a0 **0x6379a0** DoModal：内部调用 0x4d7d50 跑模态循环。
* **Create 0x6373d0(params)**，`params` 的布局：

  | 偏移 | 含义 |
  |---|---|
  | +0, +4 | 位置；0x7fffffff 表示屏幕居中 |
  | +8 | 父窗口 |
  | +0xc | 标题字串，显示在 0x1dd9 |
  | +0x10 | 模式（mode） |
  | +0x14 | 是否显示「決定」 |
  | +0x18 | 最少选几个 |
  | +0x1c | 最多选几个 |
  | +0x20 | 势力对象（0 = 玩家势力） |
  | +0x24, +0x28 | 两条帮助文字 |
  | +0x2c, +0x30 | 两个回调 |

  Create 的过程：
  1. 载入布局组 0x9b。
  2. `new 0x8afb4` → MapUI ctor 0x63e5f0（0x637608）。
  3. `MapUI::Init(&pos, ebp, playerForceId, this)`（0x640460，调用点 0x637653）。
  4. `MapUI+0x8c = (mode==4)`（0x63d500）。
  5. 建 4 个子面板，设所有标签文字：背景/勢力/軍團/士兵/資金/兵糧/顯示/都市/港關/部隊/外交/賊/街道/分布/災害/漢帝/決定/返回/一覽（字串在 0x7e9980.. 和 0x7ecc0c）。
* 宿主字段：

  | 偏移 | 含义 |
  |---|---|
  | +0x18c | 场合类型：mode，mode 4 时记为 1 |
  | +0x190 | 观察方势力对象 |
  | +0x194 | 是否有「決定」 |
  | +0x198 | 最少选几个 |
  | +0x19c | 最多选几个 |
  | +0x1a0 | **MapUI\*** |
  | +0x1a4 | 悬停信息卡（ctor 0x638600，布局 0x1db5，右上 147×199；据点用 0x637ac0，部队用 0x635d80） |
  | +0x390 | 外交图例（vt 0x857e38，布局 0x1db4）；只在外交位打开时显示 |
  | +0x51c | 軍團图例（vt 0x858010，布局 0x1db3） |
  | +0x6a8 | 数值分级图例（vt 0x8581e8，布局 0x1db3） |
  | +0x834, +0x8c4 | 帮助文字 |
  | +0x954, +0x958 | 回调 |
* **入口**：
  * **0x61d1c0** = 大地图上的「中地圖」。mode=4，不能选据点（最少 = 最多 = 0），隐藏「決定」和「一覽」，只剩「返回」。
    关闭后把背景模式存到 **[0x8bb1cc]**（初值 −1 → 勢力），把显示位存到 **[0x8bb1c8]**（初值 0x3f）；下次打开时用 0x636b60 / 0x636bb0 恢复。
  * 0x61d1c0 由 0x57e755 调用（0x57e640 里 `[this+0x34]==1` 的分支，0x580007 轮询），或由 0x57de90 直接 `jmp`（0x57de90 的调用者是 0x6315eb，推测是菜单按钮 [I]）。
  * 其它 4 个打开函数是派生类 vt 0x84c150 的「在中地圖上选据点」对话框，从列表界面打开，ctor 调用点 0x64c61f 等：

    | 打开函数 | mode |
    |---|---|
    | 0x64bea0 | 0 |
    | 0x653350 | 1 |
    | 0x651200 | 2 |
    | 0x64f7e0 | 3 |

    它们共用同一个 MapUI，所以任何对 MapUI 的补丁都会同时作用于这些选择界面。

### 1.3 据点按钮控件（vt 0x8594a0）

* 这些按钮只在**选择模式**里才显示、可点（0x63f0f0 → 0x63d100：设 ctrl+0x80 = 建筑，Show，Enable）。
  普通「中地圖」（mode 4）里它们一直隐藏，所以全部城、关、港都走 §3.5 的标记精灵。
* 按钮字段：+0x78 建筑 id，+0x7c 观察方势力，+0x80 建筑指针，+0x84 外观状态 0..3，+0x88 是否已选。
* 方法：Draw 0x63e2e0（槽 7），命中测试 0x63e4e0（按图片 alpha ≥ 0x20），外交徽章 0x63e120。

### 1.4 怎样判断「这一帧中地圖开着」

1. **全局变量（推荐，最便宜）**：0x89e00c 是一个设备对象，它的 +0x14/+0x18 是「设备重建后的回调」(fn, ctx)，地址就是 **0x89e020 / 0x89e024**。
   * MapUI::Init 在 0x64056b–0x640580 先把旧值存到 +0x1c/+0x20（0x89e028/0x89e02c，0x4010e0），再装上 (0x640340, MapUI\*)（0x4010c0）。
   * MapUI::Destroy 在 0x63d190–0x63d19f 调 0x430710（清成 0），再调 0x4010f0 恢复旧值。
   * 所以只要 `*(uint32_t*)0x89e020 == 0x640340`，中地圖（或它的某个选择变体）就开着，`*(void**)0x89e024` 就是 MapUI。
   * 父对话框 = `*(void**)(MapUI+0x20)`；`MapUI+0x8c == 1` 说明是从大地图打开的普通中地圖。
   * 风险 [I]：0x431143（全屏事件图）也会改这个槽。中地圖模态期间应该不会出现事件图。
2. **每帧必然执行的函数**：MapUI::Draw 0x63e780（vt 0x859670 槽 7）。
   * 实测 trace 里 `0x42ed43 ← 0x4303b6 ← 0x63e873` 一共 108,366 次，同期帧数 105,964 [V]。
   * 最简单的挂法是改 .rdata 里的槽 0x85968c（先 VirtualProtect），不用改代码。
   * ecx = MapUI；[esp+4] → `{POINT 父窗口屏幕原点; RECT 裁剪}`。
3. 也可以挂 ctor 0x63e5f0 / dtor 0x63e6f0，在 DLL 里自己记一个全局指针。

> 注意：中地圖开着的时候**大地图的 3D 场景照样每帧渲染**（trace 里大地图的城名牌也是每帧都画），中地圖是盖在上面的模态对话框。

## 2. 面板矩形与 hex ↔ 像素换算

### 2.1 面板矩形

* MapUI 是对话框的子窗口。位置来自布局记录 **0x1db6**（表 0x7f1ad0，0x18 字节/条：+0 组号，+4 id，+6 种类，+8 父记录，+0xe x，+0x10 y，+0x12 w，+0x14 h）：组 0x9b，(163,50)，628×628。
* 尺寸写死在 0x64049e（`mov eax,0x274`）。
* 对话框 0x9b 的顶层记录（0x1d9a..0x1dd9）外包框是 965×732。参数位置 = 0x7fffffff 时居中（0x6374f1–0x637557；0x4300a0 / 0x4300b0 取屏幕宽 / 高）。
  1920×1200 下面板左上 = **((1920−965)/2+163, (1200−732)/2+50) = (640, 284)**，与观察到的 (640, 286) 一致。
* 面板内：四周 14 像素是边框，**地图区 = 面板 + (14..614, 14..614)，每格 3 像素，200 格 = 600 像素**。
* Draw 0x63e780 计算屏幕坐标的方式：
  * `x0 = 父原点.x + MapUI[+0xc]`，`y0 = 父原点.y + MapUI[+0x10]`（0x63e7a4 + 0x472870）。
  * 底图四边形 `(x0, y0)–(x0 + [+0x14], y0 + [+0x18])`，UV 为 (0,0)–(0.61328125, 0.61328125)，常量 `0x3f1d0000` 在 **0x63e845 / 0x63e84d**（= 628/1024）。
  * 纹理 [0x89e01c]，用 0x430360 画（返回地址 0x63e873），SetTexture 在 0x63e855（返回地址 0x63e85a）。

### 2.2 hex → 面板像素：0x63ee40(out POINT\*, const u32\* pos)

```
vx = (u16)(lo*4 + 0x70)             vy = (u16)(((lo&1) + 2*hi + 0x38) * 2)   // 即 4*hi + 2*(lo&1) + 0x70
px = (i16)(vx-0x70) * 600 / 800 + 14  = 3*lo + 14
py = (i16)(vy-0x70) * 600 / 800 + 14  = 3*hi + (lo&1) + 14      （C 截断；奇数 lo 下移 1 像素）
```

* `pos` 是建筑或部队 vt+0x3c 返回的指针，指向打包的 `lo | hi<<16`（建筑 +0x1e）。
* 结果是**面板内**坐标，标记中心 = 面板左上 + (px, py)。
* **lo 对应横轴（西→东），hi 对应竖轴（北→南）**。
  验证：Scen000.s11 的 87 个据点坐标代入公式，在区域编号图里查到的编号等于据点 id 的有 **49/87**——42 个城全部吻合，另外 7 个关/港吻合。
  这和 COORDS §2.3「剧本里关/港坐标是过时的，10 关错 3、35 港错 31」完全一致 [V]。
  例：襄平 (174,16) → (536,62)；永昌 41 号 (5,191) → (29,588)。
* 16 位够用：lo ≤ 8163 都不会溢出，1800×1000 的世界没有问题。

### 2.3 面板像素 → hex：0x63d320(const POINT\* local) → `lo | hi<<16`

```
t  = (u16)(x-14) * 800 / 600          （无符号；x<14 时回绕成很大的数）
lo = trunc(t/4)                      ≈ (x-14)/3
u  = (u16)(y-14) * 800 / 600
hi = trunc((u - 2*(lo&1)) / 4)
```

只有一个调用点：0x63d7bf，在 0x63d790 左键按下里（§4.2）。

### 2.4 所有用到坐标的地方

* **0x63ee40 只在 0x63fd00（标记布局）里被调用**：
  * 0x63fd54：id < N（城、关、港）。顺便把对应按钮移到 `中心 − 尺寸/2`（vt+0x3c）。
  * 0x63fdf2：id ≥ N 且设施类型 14/15（根據地）。
  * 0x63fe77：部队 0..999。
* 0x63fd00 只在 Init 0x640460 里被调用（0x64058e），所以**每打开一次只算一次**。
  这个函数没有参数（thiscall MapUI），重复调用不会出问题：它只重写 +0/+4/+8/+0xc/+0x10 和按钮位置，不碰闪烁字段。
* 用这些坐标的地方：
  * 绘制：0x63dc40（标记）、0x63d910（外交徽章）、0x63dab0（災害/漢帝图标）、按钮的 Draw 0x63e2e0 / 0x63e120（按钮位置）。
  * 悬停命中：0x63de30（标记）、0x63e4e0（按钮）、0x63df80（标记矩形，用来放提示框）。
* 街道、水路、边界、河流**都是预画的位图**，不经过任何 hex 换算（§3）。
* 像素 → hex 只用在点击跳镜头（0x63d320 ← 0x63d790）。

## 3. 各图层怎么画、数据从哪来

### 3.1 合成：0x640260（MapUI::Compose）

* 调用者：
  * Init（0x640587）
  * SetBgMode 0x6402d0（0x6402dc）
  * SetFlags 0x6402f0，只在 0x20 位变化时（0x640317）
  * 设备重建回调 0x640340（0x640348）
* 流程：
  1. `[0x89e01c]->LockRect(0)`（vt+0x4c）。
  2. **0x63fec0**：把第 0 张图（628×628 32 位底图）用 0x454e30 拷到纹理 (0,0)。
  3. 若 +0x78 ∈ 0..4：**0x63ff30** 叠领地色。
  4. 若 +0x80 & 0x20：**0x640110** 叠街道图。
  5. UnlockRect（vt+0x50）。
* 纹理 [0x89e01c] 是共享的 1024×1024 A8R8G8B8 纹理，0x4021ed 里用 `0x44d0a0(...,0x400,0x400,...)` 建，存在 0x89e00c+0x10；事件图片、剧本界面等也用它。
  每帧只画一个四边形（§2.1），**不是每帧逐格画**。
* 写纹理时的混合（格式 0x15）：`dst = dst + ((src − dst)·A >> 8)`（每个通道，A 取源 alpha）；其它格式走 0x63d1d0（16 位）。

### 3.2 资源 midmap.wft

* `[0x8a5d14] != 0` 时从资源包读（0x401160，资源 **0x12f9**）；否则读散文件 `media/ui/midmap.wft`（字串 0x859488，指针 0x8bbd80）。
* 资源包 `Media/san11pkres.bin` 是 LINK 格式：头部 `'LINK'`，+4 是条目数，(offset,size) 表从 16+8·i 开始。
* 0x12f9 = 3,550,520 字节，格式 `WFTX0010`：u32 总长，u32 图数 = 3，然后每张图 `u16 w, u16 h, u32 fmt` + 像素。
  * **图 0**：628×628，fmt 32，BGRA，上→下。光荣手绘的中国：羊皮纸底、山、灰绿色的大河河道、深蓝色的海、四角云纹边框。
    alpha 在 200–255 之间。**图上没有城标、没有边界。**
  * **图 1**：628×628，fmt **0x108**（8 位 + 调色板），**调色板（1024 字节）在像素之后**。像素值是**光荣编号的区域 / 据点 id**：

    | 像素值 | 含义 |
    |---|---|
    | 0..41 | 城 |
    | 42..86 | 关 42..51、港 52..86 |
    | **87** | 不属于任何区域（海、山、边框，129,977 像素） |
    | **255** | 1 像素宽的区域边界线（10,860 像素） |

    没有其它值 [V]。文件里的调色板是占位，运行时被整个改写。
  * **图 2**：628×628，fmt 32，带 alpha 的叠加层：**街道（黄褐色）和水路（蓝色，沿大河）**，46,900 个非透明像素。
* 内存里每张图一条 0x28 字节的记录，数组指针在 MapUI+0x8afa8：+0 w，+2 h，+4 位深 (u8)，+0x1c 调色板指针；0x451360(img,0) 返回像素指针，行宽 = `(bpp/8·w + 3) & ~3`。
* 解出来的 PNG 在临时目录 `scratchpad/midmap/`：mm0_rgb.png、mm1_classes.png、mm2_onwhite.png、midmap_idx.npy。

### 3.3 领地着色：0x63ff30

* 对 256 个调色板项调用 **0x63eda0(&c, i)**（按 +0x78 跳转，跳转表 0x63ee28），写成 R,G,B,A；然后对 628×628 每个像素 `c = pal[idx]`，A > 0 时混合。
* 每种模式的取色：

  | 模式 | 函数 | 颜色 |
  |---|---|---|
  | 0 勢力 | 0x63eae0 | `building(i)` 的所属势力 → `0x47d3e0(force+0x44)`，alpha 改成 A·80/100 = **0xCC** |
  | 1 軍團 | 0x63eb90 | 建筑所属军团；该军团的势力必须是观察方（+0x7c），颜色 `0x47dd40(军团+8)`（8 色表 0x6fae7d4），alpha 同样 ×0.8 |

## 4. 鼠标

### 4.1 光标从哪来

* 窗口系统 **0x46f6b0**（消息分发）读全局光标位置 **[0x4ed1e2c] / [0x4ed1e30]**（客户区坐标），用 0x476940 减去接收窗口的屏幕坐标，然后按消息调虚函数 `(原始目标窗口, wParam, POINT* 本地坐标)`：

  | WM_MOUSEMOVE | +0x88 |
  | WM_LBUTTONDOWN | +0x90 |
  | WM_LBUTTONUP | +0x94 |

  | WM_RBUTTONDBLCLK | +0xa4 |

### 4.2 悬停：0x63f450（槽 +0x88）

## 6. 1800×1000 世界、标记远在 200×200 以外时：会坏的地方和要改的地方

### 6.1 现在的白方块

* 当前 ini（china lo=1234、hi=436）下，日志里 OBJS 已经整体平移了 (2468,872) 半顶点，所以建筑坐标是全局的。
  按 0x63ee40，任何标记的面板内坐标都是 `(3·lo+14, 3·hi+(lo&1)+14)`：
  * **光荣的 42 城**：px ≥ 3716，屏幕 x ≥ 4356，完全出屏，**不可能出现在面板里**。
  * **能落在屏幕上的**只有 lo ≲ 420（最西边）的据点；hi > 205 时就在面板下方。
* 新城默认无主，着色精灵 0x339 用白色，画出来就是一个个白方块。0x436210 不裁剪，所以画在了面板外面。
* 如果看到面板里「光荣城的位置是对的」，那很可能其实是预画的领地色、边界和道路（它们与坐标无关），不是城标。
  也可能那次测试用的是 china 0,0 的配置 [I]。建议实测读一下 building[0]+0x1e 核对。

### 6.2 现有的 M7 caves 在中地圖调色板里引入了编号错误（推断，需实测）[I]

* `worldmod_bases_caves.txt` 第 717–721 行把调色板取色函数的上界 `cmp eax,0x57` 改成了 N（0x63eaff、0x63ebb7、0x63ec6f、0x63ecdf、0x63ed4f）。
  但这里的 eax 是**调色板下标**，也就是 midmap.wft 图 1 里光荣的编号，不是新编号的据点 id：
  * 下标 42..86 原本是关/港，现在被当成新城 42..86 去取色。关/港真正的 id 已经变成 C..C+44。
  * 下标 87（海、山、边框，13 万像素）现在被当成建筑 87（一个新城）。
    * 勢力 / 軍團模式下，只要这座新城被占领，**整片海和空白都会染成该势力的颜色**。
    * **士兵 / 資金 / 兵糧模式不检查所属**，新城兵、金、粮都是 0，会得到 0 级颜色（ffffffff / fffff0f5 / ffeeffe6），**不透明**，于是整片海和外框变成近白色。
* 正确的映射：

  | 下标 | 映射到 |
  |---|---|
  | < 42 | 原 id |
  | 42..86 | 加 (C−42) |
  | 87..254 | 透明 |
  | 255 | 黑 |

  这些 caves 应改成这样的重映射，或者干脆不再用这张图（见 6.3）。

### 6.3 要做世界版中地圖必须处理的点

1. **坐标换算**：
   * hex → 像素：改 0x63ee40（只有 3 个调用点，都在 0x63fd00），换成新的视图变换（世界原点、缩放）。看不见的对象要剔除：把条目的种类写成 −1 并隐藏对应按钮（0x475290），因为**绘制和命中都不裁剪**。
   * 视图改变（滚轮、拖动）后重新调用 0x63fd00（thiscall，无参数）。
   * 像素 → hex：改 0x63d320（唯一调用点 0x63d7bf），必须返回全局 hex。现在它返回的是中国局部 0..199，点击中国会把镜头跳到世界西北角 (0..199, 0..199)，**这是现存的 bug**。
2. **底图、领地、边界、街道**：全是 628×628 的中国位图，而且区域编号图只有 8 位、按光荣编号，装不下 255 个据点。需要整体替换：
   * 方案一：替换 Compose 0x640260 的函数体，把自绘地图写进 [0x89e01c]（1024×1024，可锁定）。
     0x640260 的 4 个调用点都会自动走新代码，设备重建回调也会自动重画。
     底图四边形可以保持 628²，UV 常量在 0x63e845 / 0x63e84d；要更大的面板就改 0x64049e 的 0x274 和这两个 UV 常量，上限 1024。
   * 方案二：不让 0x63e780 画底图四边形（跳过 0x63e855–0x63e873），在 D3D 层自己画。
   * 无论哪种方案，合成循环里的 628 都是写死的：0x6400d9 / 0x6400ed / 0x640248 的 0x274，0x640237 的 0x9d0。
3. **缩放和平移**：MapUI 没有滚轮处理（槽 0x859718 = 0x4754d0）。可以把这个槽和 +0x88 / +0x90 / +0x94（0x8596f8 / 0x859700 / 0x859704）改指 DLL 函数，处理完再调原函数。
   1800 格放进 600 像素是每格 0.33 像素，16 像素的标记会盖住约 48 格，所以必须能缩放。
4. **点击跳镜头**：0x5723c0 的边界检查 mod 已改为 W/H，只需要 0x63d320 给出全局 hex。
5. **悬停和提示框**：完全依赖标记表里的 (x,y)（0x63de30）和按钮位置，跟着第 1 点一起就对了，不用另改。
   提示框位置 = 对象矩形右上 − 提示框高，也跟着走。
6. **固定容量**：
   * 标记表 0x4000 条（按建筑 id）和部队 1000 条，都够用。
   * 按钮 87 个，已按 N 扩大。
   * C/N 循环已由 caves 改好：0x63e88c、0x63e8f3、0x63e94c..0x63e9c1、0x63eab3、0x63f4d3..0x63fa45、0x63fd3e、0x63fe15、0x640532 等。
7. **共用**：选择模式（vt 0x84c150 派生类的 mode 0–3）和普通中地圖共用同一个 MapUI，改动会同时生效。如果只想改普通中地圖，用 MapUI+0x8c == 1 区分。

## 7. 原始观察里那些调用点是什么

* `0x42ed43 ← 0x4303b6 ← 0x4362d1`：通用 UI 精灵 0x436210，被 §3.5 的标记和按钮反复调用。中地圖的每帧精灵就是它。
* `0x42ed43 ← 0x4303b6 ← 0x63e873`、SetTexture `0x4014a8 ← 0x63e85a`：中地圖底图四边形。
* **0x632e82 / 0x6325a7 / 0x632462 / SetTexture 0x633015 都不是中地圖**。它们属于 0x632ee0，这是大地图上 3D 据点头顶的名牌和耐久条：
  * 由 0x573900 对场景物件表 0x4588338 里的物件逐个调用，0x402670 做世界 → 屏幕投影。
  * 城用图 0x1b9，关港用 0x2bb；0x632d50 画数字（数字图表 0x857c38）；0x632360 画耐久条。
  * trace 里它们每帧都有，是因为中地圖开着时大地图仍在背后渲染。
